# 2026-10-06 — Django Upgrade Phases 5.4, 5.5 & 5.6: breaking-change audit, tastypie checks, migrations

Branch: `feature/django-upgrade-phase-5.4-5.6` (from `feature/django-upgrade-phase-5.2-5.3`) · Plan: [021-django-5.2-breaking-changes-tastypie-migrations.md](../plans/021-django-5.2-breaking-changes-tastypie-migrations.md) (tasks 5.4–5.6 of [001](../plans/001-upgrade-django-to-5.2.md))

## Summary

On Python 3.14.8 + Django 5.2.18 the code review found no remaining Django 5.x breaking changes. It did find one model `save()` override that couldn't take Django's keyword arguments, which is now fixed. django-tastypie 0.15.1 works on 5.2 without patches: the API tests pass and every resource returns 200. Migrations are in sync, and coverage rose to 60% from the 55% baseline. Still open: `rebuild_index` and the browser smoke checks, which the user will run manually, plus the items that need production data or a production-like deploy.

## Changes

- **`src/title/models.py`**: `Mask.save(self)` → `save(self, *args, **kwargs)`, forwarded to `super().save()`. The old signature raised `TypeError` on `save(update_fields=…)` / `save(using=…)`
- **`src/title/tests.py`**: new `MaskTest` (mask building, plus `save(update_fields=…)`)
- **`src/run_coverage.sh`**: added `api` to `APPS` so coverage covers the same apps as `run_tests.sh`
- **`Makefile`**: new targets

## 5.5 — tastypie 0.15.1

  - **200** for the 12 model resources: resource, event, multimedia, title, issues, bibliographic, leisref, oer, community, collection, classification, institution

  - **200** for the 7 thesaurus endpoints:
